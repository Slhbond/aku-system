## 0. 这是一份什么资料

**它不是交叉编译产物，而是一个"在设备上跑的安装包"。**
里面装着 **BlueZ 5.85 和 bluez-alsa 的完整源码树**，
设备联网后由 `install.sh` 现场 `./configure && make && make install`。

这解释了为什么它跟前面几个包性质完全不同 —— 前面的是 PC 侧做好的镜像，这个是设备侧自举。

## 1. 完整蓝牙架构（逆向自 install.sh + 服务文件）

```
                  Broadcom BCM43438 (AMPAK AP6212)
                  ├── WiFi 侧：SDIO  → brcmfmac
                  └── 蓝牙侧：UART3 → /dev/ttyS3 @ 1,500,000 bps
                            │
        ┌───────────────────┘
        ↓
   [btstart.service]
   brcm_patchram_plus -d --patchram /lib/firmware/brcm/bcm43438a0.hcd
                      --enable_hci --no2bytes --tosleep 1000
                      --baudrate 1500000 /dev/ttyS3
        │  下载 RAM patch（38 KB HCD），挂 hci_uart H4 线路规程
        ↓
      hci0
        │
        ↓
   [bluetooth.service]  BlueZ 5.85（设备上现编，--enable-experimental）
        │
        ├── [aku-bluetooth-agent.service] → /usr/bin/aku_auto_pair
        │        自动配对代理（org.bluez.Agent1，RequestConfirmation /
        │        AuthorizeService / RequestAuthorization 全放行）
        │
        ├── [aku-volume.service] → /usr/bin/aku_volum
        │        读 /dev/input/event0、event1（硬件按键）
        │        → amixer set 'Power Amplifier' <值>
        │        ⚠️ install.sh 里这条是**注释掉没启用**的
        │
        └── [bluealsad.service] → bluealsad -S -p a2dp-sink -c AAC -c SBC
                 ↓  A2DP 接收端（音箱模式），支持 AAC + SBC
            [bluealsad-aplay.service] → bluealsa-aplay -S --volum=software
                 ↓
               ALSA（sun4i-codec）→ PD20 功放使能 → 喇叭
```

**一句话：这套东西把 AKU 做成了一个"支持 AAC 的蓝牙音箱"。**

## 2. install.sh 逐段拆解

| 步骤 | 命令/动作 | 说明 |
|---|---|---|
| 1 | 检查 `wlan0` 有没有 IP，没有就 `nmcli d w c` 连 WiFi | 装包前必须先联网 |
| 2 | `timedatectl set-timezone Asia/Shanghai` + 人工确认日期 | **时间不对会导致 apt 装包失败** |
| 3 | `apt-mark hold openssh-server` + `apt upgrade -y` | 防止升级时把自己 SSH 断了 |
| 4 | 装编译依赖 | 见下表 |
| 5 | **编译 BlueZ 5.85** | `./configure --prefix=/usr --mandir=/usr/share/man --sysconfdir=/etc --localstatedir=/var **--enable-library --disable-cups --enable-experimental --disable-network**` → `make && make install` |
| 6 | **编译 bluez-alsa** | `autoreconf --install` → `mkdir build && cd build` → `../configure --enable-manpages **--enable-aac**` → `make && make install` |
| 7 | 拷文件 | banner / hcd / 二进制 / service |
| 8 | `systemctl enable` 五个服务 | btstart、bluetooth、bluealsad、bluealsad-aplay、aku-bluetooth-agent |

### 编译依赖（第 4 步原文）

```bash
sudo apt install -y git vim curl build-essential autoconf automake pkg-config dialog \\
    libsystemd-dev libudev-dev libical-dev libreadline-dev libtool libdbus-1-dev \\
    libglib2.0-dev libsbc-dev libfdk-aac-dev libopenaptx-dev docutils
```

### bluez-alsa 的编解码器支持（从 `build/config.log` 实测）

| 编解码器 | 状态 |
|---|---|
| **SBC** | ✅ 启用（基础必备） |
| **AAC** | ✅ **启用**（`--enable-aac` + `libfdk-aac-dev`） |
| aptX | ❌ 未启用（`ENABLE_APTX_TRUE='#'`） |
| aptX-HD | ❌ 未启用 |

| mSBC（HFP 宽带语音） | 源码里有 `codec-msbc.c` / `sco-msbc.c` |

→ 实际运行参数 `-c AAC -c SBC` 与编译结果一致。

## 4. ⚠️ 为什么这套在 Alpine 上跑不了

| 组件 | Ubuntu 22.04 | Alpine 3.19.9 | 问题 |
|---|---|---|---|
| **libc** | glibc | **musl** | `aku_auto_pair`/`aku_volum`/`brcm_patchram_plus` 是 **glibc 动态链接**，musl 下直接跑不了 |
| **init 系统** | systemd | **OpenRC** | 5 个 `.service` 全部需要改写成 OpenRC 脚本 |
| **bluez** | 5.85（自编） | apk 装的（版本较旧） | 缺 `--enable-experimental` 的特性 |
| **bluez-alsa** | 自编 + AAC | Alpine 仓库有没有需确认 | AAC 支持要自己编 |
| **包管理** | apt | apk | `install.sh` 完全不可用 |

**结论：这套蓝牙包是给 Ubuntu 22.04 量身定做的，Alpine 上必须整套重做，不能照搬。**

> 这也正好解释了我之前发现的"Alpine 上没有 `brcm_patchram_plus`、没有任何程序加载 HCD" ——
> **不是配置漏了，是这套蓝牙方案压根还没移植到 Alpine 上。**

## 5. 移植到 Alpine 的步骤

好消息：**BlueZ 5.85 和 bluez-alsa 都是可移植的 C 代码，源码就在包里**，Alpine 上重新编即可。

### 5.1 装编译依赖

```sh
apk add build-base autoconf automake libtool pkgconf \
        dbus-dev glib-dev eudev-dev readline-dev \
        libical-dev systemd-dev \
        sbc-dev fdk-aac-dev \
        linux-headers
```

> `libopenaptx-dev` 在 Alpine 里叫 `libopenaptx` / `aptx`，视仓库而定；
> 反正 `--enable-aac` 才是关键，aptX 不是必需的。

### 5.2 编译 BlueZ 5.85

```sh
cd bluez-5.85
./configure --prefix=/usr --mandir=/usr/share/man --sysconfdir=/etc \\
            --localstatedir=/var --enable-library --disable-cups \\
            --enable-experimental --disable-network
make -j4
make install
```

> Alpine 是 musl，`configure` 应该能过；如果 `systemd-dev` 相关报错，
> 加 `--disable-systemd`（但这样 `bluetoothd` 的 systemd 集成会关掉，OpenRC 下本来就无所谓）。

### 5.3 编译 bluez-alsa（带 AAC）

```sh
cd bluez-alsa
autoreconf --install
mkdir -p build && cd build
../configure --enable-manpage --enable-aac
make -j4
make install
```

### 5.4 把 systemd 服务改写成 OpenRC

**btstart**（最关键的一个）：

```sh
cat > /etc/init.d/btstart <<'EOF'
#!/sbin/openrc-run
name="Broadcom Bluetooth Firmware Patch"
description="Download BCM43438 RAM patch and attach HCI"
command="/usr/bin/brcm_patchram_plus"
command_args="-d --patchram /lib/firmware/brcm/bcm43438a0.hcd --enable_hci \\
              --no2bytes --tosleep 1000 --baudrate 1500000 /dev/ttyS3"
command_background=true
pidfile="/run/btstart.pid"
depend() { after bluetooth; before bluealsad; }
EOF
chmod +x /etc/init.d/btstart
rc-update add btstart default
```

> ⚠️ `brcm_patchram_plus` 是 **glibc 二进制**。Alpine 上两条路：
> **(a)** 用你已经有的 `glibc-libs/` 兼容层跑它（最快）
> **(b)** 用 BlueZ 自带的 `hciattach /dev/ttyS3 bcm43xx 1500000 flow` 替代（原生 musl，推荐）

**bluealsad**：
```sh
cat > /etc/init.d/bluealsad <<'EOF'
#!/sbin/openrc-run
name="bluez-alsa daemon"
command="/usr/bin/bluealsad"
command_args="-S -p a2dp-sink -c AAC -c SBC"
command_background=true
pidfile="/run/bluealsad.pid"
depend() { need bluetooth; after btstart; }
EOF
chmod +x /etc/init.d/bluealsad
rc-update add bluealsad default
```

**bluealsad-aplay**：
```sh
cat > /etc/init.d/bluealsa-aplay <<'EOF'
#!/sbin/openrc-run
name="bluealsa-aplay"
command="/usr/bin/bluealsa-aplay"
command_args="-S --volum=software"
command_background=true
pidfile="/run/bluealsa-aplay.pid"
depend() { need bluealsad; }
EOF
chmod +x /etc/init.d/bluealsa-aplay
rc-update add bluealsa-aplay default
```

### 5.5 ⚠️ 两个自定义程序的源码不在包里

`aku_auto_pair` 和 `aku_volum` **只有编译好的 glibc 二进制，没有 .c 源码**。

从二进制里能看出它们引用的源文件是：
- `aku_auto_pair.c`
- `akumain.c` + `button_listener.c`（aku_volum 用的）

**三个选择：**

| 方案 | 做法 | 难度 |
|---|---|---|
| **A. glibc 兼容层** | 用你已有的 `glibc-libs/` 直接跑这两个二进制 | ★☆☆☆☆（最快） |
| **B. 自己重写** | 功能都很简单：<br>• `aku_auto_pair` = 注册一个 BlueZ Agent 自动放行配对<br>• `aku_volum` = 读 `/dev/input/event*` 按键 → `amixer set 'Power Amplifier' N` | ★★☆☆☆ |
| **C. 不要它们** | 手动用 `bluetoothctl pair/trust/connect`，音量用 `alsamixer` | ★☆☆☆☆（功能少一点） |

> **方案 B 其实很划算** —— 这两个程序逻辑简单，重写成 musl 原生程序后彻底摆脱 glibc 依赖。
> `aku_volum` 的行为从 strings 就能完全还原：读输入事件 → `amixer set 'Power Amplifier' %d`。

## 6. 排错要点（来自 install.sh 的提示 + 实测）

install.sh 开头自己列了三条：

1. **WiFi 名称不能出现中文，必须 2.4G** —— BCM43438 只支持 2.4 GHz，5G 连不上
   - 连不上时试试**改 WiFi 信道**（有些信道兼容性差）
2. **系统时间必须正确**，否则 apt 装包会失败（TLS 证书校验）
3. 安装完**手动重启**

再加上我这边发现的：

4. **不要同时用两套蓝牙固件加载方式** —— 见下文第 7 节
5. `aku-volume.service` 默认是**注释掉的**，需要按键调音量得手动 `systemctl enable`

## 7. 关于蓝牙串口的一个疑点（仍然成立）

前面分析原厂固件时发现：

- 原厂 `/etc/bluetooth/btenable.sh` 用的是 **`/dev/ttyS1`** + `bsa_server` + `rfkill0/state` 上电时序
- 这套新方案用的是 **`/dev/ttyS3`** + `brcm_patchram_plus`

**⚠️ mainline 的 `/dev/ttyS<N>` 编号来自 DTS 的 `serial<N>` 别名，不等于硬件 UART 编号：**

```dts
aliases {
    serial0 = "/soc/serial@1c28400";   /* 硬件 UART1，却暴露成 ttyS0 */
    serial3 = "/soc/serial@1c28c00";   /* 硬件 UART3，暴露成 ttyS3 */
};
```

既然这套方案在 AKU 上**确实能用**，说明 `ttyS3` 是对的，原厂那个 `btenable.sh`
很可能是从别的板子抄来的历史遗留（而且它没有任何地方调用，是死代码）。

**但移植到 Alpine 时仍建议先确认一次**，成本很低。

## 8. 小结：Alpine 蓝牙移植清单

| # | 任务 | 难度 | 备注 |
|---|---|---|---|
| 1 | 装编译依赖 | ★ | 注意 Alpine 包名和 Ubuntu 不同 |
| 2 | 编 BlueZ 5.85 | ★★ | 源码已有，musl 下应该能过 |
| 3 | 编 bluez-alsa（`--enable-aac`） | ★★ | 同上 |
| 4 | 写 3 个 OpenRC 服务 | ★ | 照抄上面的模板 |
| 5 | 解决固件补丁加载 | ★ | 推荐用 `hciattach bcm43xx` 代替 glibc 的 `brcm_patchram_plus` |
| 6 | 处理 `aku_auto_pair`/`aku_volum` | ★★ | 推荐自己重写（逻辑简单） |
| 7 | 确认 UART | ★ | 先量 PG3/PG4 vs UART3 引脚 |

**做完这 7 步，Alpine 的蓝牙就能达到和 Ubuntu 一样的水平。**
