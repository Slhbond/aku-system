# Q2：大佬有 Ubuntu 了，我成功的几率大吗？（初次评估）

## 你的问题

> 我要是告诉你有大佬写了一个Ubuntu系统呢正常能用音频和屏幕都可以用也给我了一些资料
> 但是他的WiFi和蓝牙效果没有原系统好我给你资料参考你感觉你成功的几率大吗

## 回答要点

### 先纠正一个方向性问题

**你担心反了。** WiFi/蓝牙恰恰是**最容易**的部分，因为：
- BCM43438 是**树莓派 3 同款芯片**，brcmfmac 用户基数巨大，坑早被踩平
- **我手上有原厂调校好的文件**（NVRAM / HCD / 3 份固件）
- 关键发现：**原厂 NVRAM 根本没调过**（原文写着 `just placeholders, need to be updated`，MAC 还是 Broadcom 默认值）
  → 说明原厂 WiFi 也没做板级调校，**主线只要配置对就该打平**

### 分层概率（当时的估计）

| 大佬给到的程度 | 复现系统 | WiFi 追平 | 蓝牙追平 |
|---|---|---|---|
| 源码级 | ~95% | ~80% | ~55% |
| 二进制级 | ~85% | ~80% | ~55% |
| 只有描述 | ~40% | ~60% | ~40% |

蓝牙 55% 的天花板来自 **BSA vs BlueZ 的协议栈差异**。

### 最想要的资料（按优先级）
1. Ubuntu **完整镜像 dump**（信息量最大，可直接和原厂 diff）
2. `.dts` 或 `.dtb`（二进制也行，能反编译）
3. 内核 `.config` 或源码树
4. `dmesg`、`iw reg get`、蓝牙相关日志

## 事后修正

拿到资料后发现实际情况**比预想的好**：
- 大佬不是换用户态，而是**彻底的 mainline 移植**（Linux 6.1.9 + U-Boot 2023.01）
- 蓝牙也不是只有 `brcm_patchram_plus`，而是**整套 BlueZ 5.85 + bluez-alsa（支持 AAC）**
- 所以蓝牙那 55% 的估计偏悲观了 —— 详见 Q6

## 结论
**几率挺大**，而且最大的石头（音频+屏幕）已被大佬搬走。
