# Q6：移植 Alpine 的 WiFi/蓝牙达到原厂效果，概率多大？

## 你的问题

> 你感觉移植 alpine WiFi 和蓝牙做到原厂效果概率多大

## 直接回答

| 目标 | WiFi | 蓝牙 |
|---|---|---|
| **能用** | 95% | 85% |
| **体感与原厂无差别** | **80%** | **60%** |
| **全面超越原厂** | 65% | 45% |
| **两个同时达到原厂水平** | | **约 50%** |

## 支撑判断的两个硬数据

### ① 蓝牙 HCD 固件 —— 三份完全相同 ✅

```
原厂       e83ba393b7550d56addd04b05860c8be  bcm43438a0.hcd
Ubuntu     e83ba393b7550d56addd04b05860c8be
BT 安装包   e83ba393b7550d56addd04b05860c8be
```
→ 蓝牙**射频层固件是同一份**，差异只能来自协议栈和主机侧集成。

### ② WiFi 固件 —— 是不同构建 ⚠️

```
原厂       fw_bcm43438a0.bin            378,595 B   (bcmdhd 用)
新系统     brcmfmac43430a0-sdio.bin     382,455 B   (brcmfmac 用)
```
→ 同芯片的**不同 Broadcom 发布版本**。影响特性而非射频功率。

## 为什么 WiFi 给 80%（结构性优势）

「WiFi 效果」主要由三件事决定，**你基本都占了**：

| 决定因素 | 状况 |
|---|---|
| **射频功率 / 灵敏度** | 由 **NVRAM** 决定 —— 你的和原厂**逐字节相同** ✅ |
| **天线 / 射频走线** | 同一块板 ✅ |
| **管制域** | 原厂 `ccode=ALL` 无限制；你装了 `wireless-regdb`，只需 `iw reg set CN` ✅ |
| **省电模式** | Alpine 无 NetworkManager，天然没有强制省电 ✅ |

### WiFi 的风险点

1. **`max-frequency = <10000000>`（10 MHz）可能是自设的吞吐上限**
   - SDIO 4-bit @ 10 MHz ≈ 40 Mbps 理论带宽
   - 而 802.11n 1×1 20MHz 实测 TCP 能到 ~35 Mbps
   - **这个时钟很可能正好卡在脖子上**。原厂 bcmdhd 大概率跑 50 MHz
   - **建议试 25 MHz**（10 MHz 稳 / 50 MHz 快，25 大概率是甜点）
2. WiFi 固件是不同构建
3. brcmfmac 的速率自适应/漫游策略与 bcmdhd 不同

## 为什么蓝牙只给 60%（结构性劣势）

### ① 协议栈整个换了 —— 这不是配置问题，是实现问题

原厂是 Broadcom 私有 **BSA**（`bsa_server` 1.69 MB + `libbsa.so`），新系统是 BlueZ 5.85。
profile 支持、A2DP 实现、功耗策略都不同。

### ② 内核里没有 `hci_bcm` / `btbcm` —— 最值得担心的一条

核对 `modules.builtin`：
```
btbcm     builtin=0  module=0     ← 没有
hci_bcm   builtin=0  module=0     ← 没有
```

后果：DTB 里这三个 GPIO **没有任何驱动去管**
```dts
shutdown-gpios      = <&pio 4 10 1>;   // PE10  BT 电源
device-wakeup-gpios = <&pio 1 3 1>;    // PB3
host-wakeup-gpios   = <&pio 6 1 1>;    // PG1
```

**WiFi 和蓝牙共用同一根天线，共存靠这些信号握手。** 没人管它们，共存只能靠硬件默认状态 ——
**这很可能就是「蓝牙不如原厂」的真正原因。**

原厂还有 `rfkill0/state` 做 BT 上电时序，新系统也没这个驱动。

### ③ 反过来说，音质可能更好 ✅

用户在 bluez-alsa 上开了 `--enable-aac`（从 `build/config.log` 确认 `ENABLE_AAC_TRUE=''`），
而原厂 BSA 那套大概率只有 SBC。**如果音源支持 AAC，你的音质应该比原厂好。**

## 能把概率显著拉高的三件事

| # | 动作 | 效果 |
|---|---|---|
| 1 | **先测出基线数字**（三套系统、同位置、同 AP） | 没有基线，前面所有概率都是纸上谈兵 |
| 2 | 试把 SDIO 时钟从 10 MHz 提到 25 MHz | WiFi 吞吐最直接的一刀 |
| 3 | 把 `hci_bcm`/`btbcm` 编进内核 | 蓝牙最值得做的一步，恢复共存握手 |

## 一句话总结

> **WiFi 我很有信心（80%）** —— 决定 WiFi 好坏的东西（NVRAM、天线、管制域）你都已经对了，剩下的是调参。
>
> **蓝牙我给 60%** —— 换的是整套协议栈，而且缺了 GPIO 共存管理这一环。
> **它不会「调不好」，但可能「调不回一模一样」**。音质大概率反而更好，但连接稳定性和距离才是难追平的部分。
