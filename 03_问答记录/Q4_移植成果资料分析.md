## 核心发现

### 1. 这**不是**「换用户态」，是彻底的 mainline 移植

| 项目 | 原厂 | 新系统 |
|---|---|---|
| 内核 | Linux 3.4.39 + fex | **Linux 6.1.9 主线 + 设备树** |
| U-Boot | 2011.09 | **2023.01** |
| 存储 | 私有 `/dev/nandd` 逻辑卷 | **标准 MTD + UBI/UBIFS** |
| 刷机 | — | **FEL**（`sunxi-fel`） |

（我之前的猜测是错的 —— 以为只是换 rootfs）

### 2. 两套镜像**只差 2 处**

| 文件 | Ubuntu | Alpine | 是否相同 |
|---|---|---|---|
| `uImage` | 5,947,120 B | 5,947,120 B | ✅ **MD5 相同** |
| `sunxi-spl-with-ecc.bin` | 214,464 B | 214,464 B | ✅ **MD5 相同** |
| `u-boot-sunxi-with-spl.bin` | 781,352 B | 781,352 B | ✅ **MD5 相同** |
| `sun5i_r8_akubox_linux.dtb` | 19,275 B | 19,443 B | ⚠️ **差 5 个属性** |
| `rootfs.ubi` | 142,606,336 B | 52,428,800 B | ❌ 不同 |

### 3. DTB 差异只有 5 个属性，全在 WiFi 上 ⭐

```diff
--- UBUNTU
+++ ALPINE
@@ WiFi SDIO 节点 (mmc@1c11000)
+   max-frequency = <0x989680>;          // 10 MHz
@@ PD18 引脚 pinctrl
+   output-high;                          // WL_REG_ON 上电默认拉高
@@ wifi_reg_en (mmc-pwrseq-simple)
+   post-power-on-delay-ms = <0x1f4>;     // 500 ms
+   power-off-delay-us = <0x2710>;        // 10 ms
+   clocks = <0x13>;                      // &clk_32k (32768 Hz)
+   clock-names = "ext_clock";
```

**Alpine DTB 是 Ubuntu DTB 的严格超集**（只有 `+` 没有 `-`）
→ **把 Alpine 的 DTB 刷到 Ubuntu 上，就能白拿这些修复。**

### 4. 三块「硬骨头」的解法

| 难题 | 原厂 | 大佬的解法 |
|---|---|---|
| **显示屏** | DISP/TCON + fex `[disp_init]` + DirectFB | **面板是 ST7735S**，自写 `st7735sfb` 驱动（`drivers/video/fbdev/`，编进内核） |
| **音频** | ASoC **FPGA**（`zhc_function.ko`） | **绕过 FPGA**：主线 `sun4i-a10-codec` + `allwinner,pa-gpios = <&pio 3 20 0>` (PD20) + `asound.state` |
| **WiFi** | 闭源 `bcmdhd.ko` | 主线 `brcmfmac`，**NVRAM 与原厂逐字节相同** |

### 5. 蓝牙是**后来追加**的独立安装包

> 版本串：`AKU-BLUETOOTH-260118版固件-蓝牙单独安装包最终版本`
> 作者：zheng1 (juping_zheng1@163.com)、Ice_BingQi、trz0332、HM

**里面是 BlueZ 5.85 + bluez-alsa 的完整源码树，由设备联网后现场编译。**
详见 [`Q6`] 与 [`../02_分析报告/07_蓝牙方案说明与移植.md`]

两套镜像共享同一套内核/引导器，**唯一实质差异是 DTB 的 5 个 WiFi 属性和 rootfs**。
